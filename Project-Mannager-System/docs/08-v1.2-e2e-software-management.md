# Phân hệ Quản lý Phần mềm Toàn trình (v1.2 - E2E Software Management)

Tài liệu này định hình thiết kế nghiệp vụ, giải thuật kỹ thuật, cấu trúc cơ sở dữ liệu và kế hoạch triển khai nâng cấp ứng dụng **PM Daily Work Management** đạt chuẩn quản lý dự án công nghệ toàn trình (End-to-End).

---

## 1. Phân tích Nghiệp vụ & Giải thuật Chuyên sâu

### 1.1 Thuật toán Lập lịch CPM tương tác với Sprint Timebox & Phụ thuộc
*   **Sprint Boundary Constraint**: Thuật toán CPM Forward Pass giới hạn thời gian bắt đầu và kết thúc sớm nhất:
    $$ES_i = \max\left(S_{StartDate}, \max_{j \in Pred(i)} (EF_j + Lag_{ji})\right)$$
    Cảnh báo `WARNING_OUT_OF_SPRINT_BOUNDARY` được đưa ra nếu ngày kết thúc của Task vượt quá kết thúc của Sprint ($EF_i > S_{EndDate}$).
*   **Cross-Sprint Dependency Validation**: Cho phép liên kết Task B (Sprint 2) phụ thuộc Task A (Sprint 1). Chặn và trả về lỗi `400 Invalid` nếu Task B (Sprint 1) phụ thuộc Task A (Sprint 2).

### 1.2 Mô hình Toán học EVM (Earned Value Management)
Hệ thống tính toán các chỉ số sức khỏe tài chính hàng ngày dựa trên Baseline đã được duyệt (APPROVED):
*   **Planned Value (PV)**: $PV = \sum \left( \text{Budget at Completion}(t) \times \% \text{PlannedProgress}(t, Today) \right)$
*   **Earned Value (EV)**: $EV = \sum \left( \text{Budget at Completion}(t) \times \text{ActualProgress}(t) \right)$
*   **Actual Cost (AC)**: $AC = \sum \left( \text{ActualLoggedHours} \times \text{HourlyRate} \right)$
*   **Chỉ số phân tích**: $CV = EV - AC$ (Cost Variance), $SV = EV - PV$ (Schedule Variance), $CPI = \frac{EV}{AC}$ (Hiệu quả chi phí), $SPI = \frac{EV}{PV}$ (Hiệu quả tiến độ).

### 1.3 Bảo mật Git Webhook & Regex Commit Parser
*   **Xác thực chữ ký HMAC-SHA256**: Tính toán mã băm từ Webhook Secret Token cấu hình sẵn:
    $$\text{Signature}_{\text{calc}} = \text{HMAC-SHA256}(\text{PayloadBody}, \text{SecretToken})$$
    Chấp nhận payload nếu trùng khớp với Header `X-Hub-Signature-256` hoặc `X-Gitlab-Token`, nếu không trả `401 Unauthorized`.
*   **Regex Commit Parser**: Biểu thức chính quy trích xuất task code: `^\[([A-Z0-9]+-TASK-\d+)\]\s*(.*)$`.

### 1.4 Cấu hình Đa đơn vị tính Task (Duration & Effort Units)
*   **Phương án A (Unified Base Unit)**: Lưu trữ thống nhất đơn vị **Phút (Minutes)** trong database cho mọi thuật toán CPM và tính toán.
*   **Bảng quy đổi chuẩn**:
    *   $1 \text{ Hour} = 60 \text{ Mins}$
    *   $1 \text{ Day} = 8 \text{ Hours} = 480 \text{ Mins}$
    *   $1 \text{ Week} = 5 \text{ Days} = 40 \text{ Hours} = 2,400 \text{ Mins}$ (loại trừ cuối tuần)
    *   $1 \text{ Month} = 20 \text{ Days} = 160 \text{ Hours} = 9,600 \text{ Mins}$ (quy ước 20 ngày công)

### 1.5 Cấu trúc Mẫu Wiki Dự án chuẩn hóa (Project Wiki Templates)
Wiki dự án có cấu trúc mẫu tự động nạp từ database gồm 5 cấu phần chính:
1.  **Hướng dẫn Bắt đầu (Getting Started)**: Local Env Setup, Git Branching Workflow.
2.  **Kiến trúc hệ thống (Architecture)**: System Components Diagram, Database Design, API Catalog.
3.  **Quy chuẩn viết code (Coding Guidelines)**: Code Conventions, Code Review Checklist.
4.  **Quy trình chất lượng (QA)**: Definition of Done (DoD), Defect logging flow.
5.  **Vận hành (Operations)**: Environment variables, Backup & Recovery.

### 1.6 Đồng bộ Kế hoạch con liên kết từ Milestone (Milestone-driven Detail Planning)
*   **Mối liên kết**: Thêm `parent_milestone_task_id` vào `project_plans` trỏ đến `plan_tasks` (loại `MILESTONE`) thuộc Master Plan.
*   **Đồng bộ Lịch trình & Tiến độ**:
    $$Finish_{\text{Milestone}} = \max_{j \in Tasks_{\text{Detail}}} (Finish_j)$$
    $$PercentComplete_{\text{Milestone}} = \frac{\sum_{j \in Tasks_{\text{Detail}}} \left( Duration_j \times Progress_j \right)}{\sum_{j \in Tasks_{\text{Detail}}} Duration_j}$$
    Quá trình đồng bộ chạy theo dạng Event-driven: Khi Detail Plan kết thúc Recalculate, hệ thống chỉ cập nhật dòng Milestone trên Master Plan.

## 2. Tích hợp Hệ thống & Tính liên kết Toàn trình (End-to-End System Cohesion)

Để hệ thống hoạt động như một chỉnh thể thống nhất và phục vụ quản lý dự án toàn trình hiệu quả, chúng tôi thiết kế mô hình tích hợp chéo giữa các tính năng V1.0, V1.1 và V1.2 như sau:

### 2.1 Luồng Vận hành Công việc Liên kết (End-to-End Workflow)
*   **Từ Phạm vi sang Lập kế hoạch (Epic/Story $\rightarrow$ WBS)**: Epic và User Story (V1.2) là đầu vào định hình phạm vi. Các plan_task trên WBS (V1.1) được liên kết trực tiếp với các User Story này để PM theo dõi phần trăm hoàn thành thực tế của yêu cầu nghiệp vụ qua thuật toán Roll-up tiến độ tự động.
*   **Từ Lập kế hoạch sang Thực thi (WBS $\rightarrow$ Kanban Task)**: Các WBS `plan_task` được kết nối 1:1 hoặc 1:N với các `tasks` (công việc thực thi trên Kanban - V1.0) thông qua bảng `plan_links`. Khi lập trình viên hoàn thành một Task thực thi trên Kanban (`status = DONE`), Backend sẽ tự động cập nhật tiến độ của `plan_task` tương ứng trên WBS lên `100%`, kích hoạt tính toán lại toàn bộ tiến độ Master Plan.
*   **Từ Thực thi sang Kiểm thử & Chất lượng (Task $\rightarrow$ Test Case $\rightarrow$ Issue)**: 
    *   Các Action Item (V1.0) sau cuộc họp được PM duyệt chuyển thành Task (V1.0) sẽ tự động nạp vào Backlog của Sprint (V1.2) hiện hành để giao việc.
    *   Khi viết code, lập trình viên liên kết task qua Git Webhook (V1.2). Khi PR được merged, task chuyển `DONE` và kích hoạt tự động trạng thái `READY_TO_TEST` cho các Test Case (V1.2) liên quan.
    *   Nếu Tester thực hiện Test Run (V1.2) và đánh giá một Test Step là `FAILED` $\rightarrow$ Hệ thống tự động kích hoạt tạo `Issue` (V1.0) loại `BUG`, liên kết ngược lại Test Case và giao lại cho Dev.

### 2.2 Tích hợp Giao diện người dùng (UI Integration)
*   **Mở rộng Dashboard (V1.0)**: Dashboard chính của PM hiển thị thêm 4 thành phần chỉ số:
    *   Hiệu quả tài chính EVM (chỉ số CPI/SPI dạng biểu đồ kim đo).
    *   Biểu đồ Sprint Burndown của Active Sprint.
    *   Mật độ Defect QA trên dự án.
    *   Khung lịch sử sửa đổi Wiki gần nhất.
*   **Giao diện Gantt SVG (V1.1)**: Tích hợp hiển thị các dải phân cách thời gian của Sprint (V1.2) dạng các vạch dọc mờ trên dòng thời gian và các icon trạng thái liên kết code Git trên từng thanh công việc.

### 2.3 Mở rộng Hạ tầng chung (Audit & Notifications)
*   *Notifications (V1.0)*: Bổ sung các loại thông báo in-app: khi trang Wiki bị sửa, khi Test Run hoàn thành có lỗi nghiêm trọng, hoặc khi chỉ số CPI tài chính giảm dưới mức $0.85$ (dấu hiệu dự án vượt ngân sách nghiêm trọng).
*   *Audit Log (V1.0)*: Mọi hoạt động ghi nhận Test case, sửa tài liệu Wiki, điều chỉnh đơn giá giờ nhân viên hay lưu snapshot EVM đều được ghi lại trong nhật ký hoạt động JSONB an toàn.

## 3. Kiến trúc Dữ liệu & Database Schema (Flyway Migrations)

Các tệp SQL di cư Flyway được cấu trúc tuần tự trong `db/migration/`:

### 3.1 Cấu hình Đa đơn vị tính Task
Tệp SQL di cư: `V11__add_duration_effort_units.sql`
```sql
ALTER TABLE tasks 
    ADD COLUMN estimate_unit VARCHAR(50) NOT NULL DEFAULT 'MINUTE',
    ADD CONSTRAINT chk_task_estimate_unit CHECK (estimate_unit IN ('MINUTE', 'HOUR', 'DAY', 'WEEK', 'MONTH'));

ALTER TABLE plan_tasks 
    ADD COLUMN duration_unit VARCHAR(50) NOT NULL DEFAULT 'MINUTE',
    ADD COLUMN effort_unit VARCHAR(50) NOT NULL DEFAULT 'MINUTE',
    ADD CONSTRAINT chk_pt_duration_unit CHECK (duration_unit IN ('MINUTE', 'HOUR', 'DAY', 'WEEK', 'MONTH')),
    ADD CONSTRAINT chk_pt_effort_unit CHECK (effort_unit IN ('MINUTE', 'HOUR', 'DAY', 'WEEK', 'MONTH'));

ALTER TABLE plan_template_tasks 
    ADD COLUMN duration_unit VARCHAR(50) NOT NULL DEFAULT 'MINUTE',
    ADD COLUMN effort_unit VARCHAR(50) NOT NULL DEFAULT 'MINUTE',
    ADD CONSTRAINT chk_ptt_duration_unit CHECK (duration_unit IN ('MINUTE', 'HOUR', 'DAY', 'WEEK', 'MONTH')),
    ADD CONSTRAINT chk_ptt_effort_unit CHECK (effort_unit IN ('MINUTE', 'HOUR', 'DAY', 'WEEK', 'MONTH'));
```

### 3.2 Phân hệ Project Wiki & Liên kết Milestone
Tệp SQL di cư: `V12__add_project_wiki_and_milestone_planning.sql`
```sql
CREATE TABLE wiki_page_templates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    parent_template_id UUID REFERENCES wiki_page_templates(id) ON DELETE SET NULL,
    title VARCHAR(255) NOT NULL,
    content_placeholder TEXT NOT NULL,
    sequence_no INT NOT NULL DEFAULT 0
);

CREATE TABLE project_wiki_pages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(id),
    parent_page_id UUID REFERENCES project_wiki_pages(id) ON DELETE SET NULL,
    title VARCHAR(255) NOT NULL,
    content TEXT NOT NULL,
    version BIGINT NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID REFERENCES users(id),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by UUID REFERENCES users(id),
    deleted_at TIMESTAMPTZ,
    deleted_by UUID REFERENCES users(id)
);

CREATE TABLE project_wiki_page_histories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    wiki_page_id UUID NOT NULL REFERENCES project_wiki_pages(id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,
    content TEXT NOT NULL,
    changed_by UUID REFERENCES users(id),
    changed_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

ALTER TABLE project_plans 
    ADD COLUMN parent_milestone_task_id UUID REFERENCES plan_tasks(id) ON DELETE SET NULL;
```

## 4. Thiết kế Bảo mật (Column-Level Encryption)
Đơn giá nhân sự (`hourly_rate`) trong bảng `project_members` được mã hóa đối xứng bằng thuật toán **AES/GCM/NoPadding** (AES-256-GCM) ở tầng DB. Khóa DEK được quản lý tách biệt ngoài tầng lưu trữ cơ sở dữ liệu.

## 5. Kế hoạch Kiểm tra Nghiệp vụ (Verification Plan)
1.  **Kiểm tra đồng bộ Cross-Plan**: Xác nhận tiến độ và ngày kết thúc của Detail Plan tự động cập nhật đè lên Milestone tương ứng ở Master Plan qua thuật toán Event-driven.
2.  **Kiểm tra khởi tạo Wiki**: PM kiểm tra việc tự động sinh 5 cấu phần tài liệu mẫu khi kích hoạt tính năng "Khởi tạo từ mẫu chuẩn".
3.  **Kiểm tra mã hóa tài chính**: Xác nhận cột `hourly_rate` lưu dạng mã hóa thô trong DB và giải mã chính xác trên API của PM/ADMIN có phân quyền `financial:view`.
